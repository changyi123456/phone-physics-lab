# Phylab：單位與時間解析度稽核

版本 0.3.0；日期 2026-10-08。範圍為目前 22 個內建模組、圖表、操作參數與 Excel 匯出。這是程式與資料契約稽核，不是手機硬體校驗報告。

## 教師在網頁上看到什麼

入口頁的「教師量測須知」說明物理單位、時間細節與課堂操作。每個實驗的「量測說明」在配對前就能展開，呈現功能與圖表、單位意義、取樣限制、適用情境及模型條件。切換亮暗、中英後說明一併切換。

實驗頁的「單位與時間解析度」在收資料後顯示實際取樣率 Fs、點間隔 Δt、來源間隔範圍／音訊塊間隔與電腦收到封包的中位間隔。展開後還有取樣視窗、瀏覽器回報硬體間隔（若提供）、音訊塊大小、5 ms 聲音事件判定、傳送／顯示／分析排程、RTT 與單位表。暫停或結束保留最後值，明確標記；示範值標記為模型而非硬體規格。

Excel 新增「單位與時間」，與網頁使用相同的取樣與單位函式。原始數據不因畫面取整而被截斷；PCM 完整以 float32 little-endian 保存。

## SI 結論與修正

物理計算以 s、m、kg、m/s²、rad/s、Hz、N/m 為基準。瀏覽器的角速度 °/s 在進入計算前乘 π/180；GPS 距離公式亦先將角度轉 rad。µT 是 T 的 SI 前綴形式；照度的 SI 符號統一為 **lx**。傾角與經緯度保留教學常用 °，這是 BIPM 接受與 SI 並用的非 SI 單位，網頁註明換算，傾角 Excel 另提供 rad 欄位。

數位 PCM 的 FS 是滿刻度比例，RGB/Y 是 0…255 的數位代碼，皆無量綱，不能改標成聲壓 Pa、dB SPL 或照度 lx。FFT 每個分析窗以自身峰值正規化，頻譜為無量綱相對幅度；熱圖的 0 dB 是該窗峰值，不能用顏色比較不同時間的絕對音量。事件數、R²、自相關及能量比亦無量綱。

本次修正照度的 lux→lx 標示、相機 /255 的含混標示、FFT 相對尺度註記、觸發參數的單位、擬合斜率與截距單位。補齊進階模組設定的可見輸入欄位，包含聲音門檻、運動門檻、定位精度與有效質量。數值顯示的小數位不是有效數字或量測準確度保證。

| 模組          | 顯示／計算尺度                    | 判讀重點                              |
| ------------- | --------------------------------- | ------------------------------------- |
| 加速度        | m/s²、s、Hz                       | 含重力與線性加速度分開                |
| 角速度        | rad/s、s、Hz                      | 原 °/s 另存於 Excel                   |
| 傾角          | °，Excel 同時提供 rad             | 1°=π/180 rad；是重力推導角度          |
| 單擺          | rad/s、T(s)、f(Hz)、L(m)、g(m/s²) | g 由小角度理想模型推導                |
| 彈簧振動      | m/s²、T(s)、f(Hz)、m(kg)          | 有效質量包含手機與載具                |
| 向心加速度    | m/s²、rad/s、rad²/s²              | a=rω² 的 ω 必須是 rad/s               |
| 聲音頻譜      | PCM/RMS FS(1)、Hz、s              | 相對數位音訊，不是 Pa／dB SPL         |
| 聲音頻率歷史  | Hz、s、相對 dB                    | 每窗峰值正規化，不是絕對音量歷史      |
| 聲控秒錶      | s、FS(1) 門檻                     | 約 5 ms RMS 窗＋觸發間隔下限          |
| 反彈碰撞分析  | s、模型 h(m)、E/E₀(1)             | g=9.80665 m/s²；未直接量測 J          |
| 加速度頻譜    | m/s²、Hz、相對幅度(1)             | 頻率與歸一化振幅分別判讀              |
| 振動頻率歷史  | m/s²、Hz、s、相對 dB              | 連續窗口，不能跨暫停補值              |
| 運動觸發秒錶  | m/s² 門檻、s                      | 時間受來源事件間隔限制                |
| 彈簧常數      | kg、s、Hz、N/m                    | N/m=kg/s²，k 是模型推導值             |
| 向心半徑擬合  | m、rad²/s²、m/s²、R²(1)           | 斜率與斜率標準誤為 m，截距為 m/s²     |
| GPS／戶外運動 | °、m、m/s、s                      | 路程含漂移，精度是 API 回報值         |
| 相機亮度      | 數位 Y 0…255(1)、s                | 加權像素代碼不是線性光度或 lx         |
| 相機顏色      | 數位 RGB 0…255(1)、s              | 自動曝光、白平衡與後處理會影響值      |
| 光學秒錶      | s、數位 Y 門檻                    | ROI 約 10 Hz，可能漏掉快速遮光        |
| 三軸磁場      | µT、s                             | 1 µT=10⁻⁶ T，須有原始 API             |
| 環境照度      | lx、s                             | 須有原始照度 API，不能用相機替代      |
| 教師自訂實驗  | m/s² 或 rad/s，Hz、s              | 單位隨所選 gravity／linear／gyro 改變 |

多輪 T²–L 擬合斜率為 s²/m；T²–m 為 s²/kg；截距為 s²；R² 無量綱。原始 timestamp 另存 ms，屬秒的 SI 前綴，不與相對 t(s) 混用。

## 沒有所有手機共用的「最短時間」

| 層／來源       | 現在的實作                                                     | 對老師的意義                                                                                               |
| -------------- | -------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| 運動／姿態     | 瀏覽器決定來源事件頻率；同來源最近分段的正時間間隔中位數取倒數 | 顯示的是網站能觀測的事件率，不保證是晶片原生 Hz。例：實測 50 Hz→20 ms；60 Hz→約16.67 ms                    |
| 麥克風 PCM     | 使用實際 AudioContext.sampleRate；每塊 1024 點                 | 例：48 kHz→20.83 µs／點、21.33 ms／塊；44.1 kHz→22.68 µs／點、23.22 ms／塊。可能經重取樣，不保證硬體原生率 |
| 聲音事件辨識   | 約 5 ms RMS 窗，尾窗可能較短；標記窗起點                       | 5 ms 是判定窗目標，非校準後的誤差／準確度；聲傳播、輸入延遲、門檻與最小事件間隔亦有影響                    |
| 相機 ROI       | 至少 95 ms 才取下一筆，上限約10.53 Hz；還受影片回呼影響        | 常見約100 ms或更慢，適合慢速變化；expectedDisplayTime 不是曝光瞬間，不能宣稱毫秒光閘                       |
| 瀏覽器定位     | watchPosition；更新由系統決定                                  | 無固定 Hz／最短間隔保證；可能來自 GPS 或網路                                                               |
| 原始磁場／照度 | 請求20 Hz（50 ms）                                             | 請求不是保證，可能更慢或不可用；iPhone Safari 通常不提供原始 API                                           |
| 手機傳送       | 非音訊每120 ms檢查待傳批次；音訊每塊就緒立即發送               | 一個封包可含多個來源事件／很多 PCM 點，不會只因120 ms批次就把資料降成8.33 Hz                               |
| 電腦顯示       | 約100 ms更新讀值                                               | 約10次/s是畫面排程，不是感測器率                                                                           |
| 電腦分析       | 最短600 ms排程；最多一個工作在途                               | 約1.67次/s是分析排程，CPU忙時更慢；FFT依來源時間計算                                                       |
| 網路           | 顯示資料封包接收間隔與往返 RTT                                 | RTT 不是單向延遲，也不是量測時間誤差。丟包／重送可能影響完整性                                             |

取樣間隔統計只使用最近分段、同一來源最近20秒內最多300筆；不混入姿態與運動、不跨暫停或上一輪。正間隔的 min/max 保留缺口與抖動。接收間隔使用最近最多100個有效間隔，暫停／繼續清除間隔視窗；封包總數包含重送，與樣本數不同。

時間分析使用手機的來源時間，不用電腦網路到達時間。但開始指令仍會延遲，不同手機不共享時鐘。背景、鎖屏或權限限制可中止感測，不能假設精確連續。時間戳可有小數毫秒，瀏覽器仍可因隱私而量化；沒有將瀏覽器規範的 timestamp 最細刻度宣稱成實驗準確度。

Nyquist 的 Fs/2 是理論上限；手機濾波、反混疊與事件量化會限制實用頻帶。FFT 的 bin 間距為 Fs/NFFT，實際頻率分辨能力也取決於觀測窗長與 Hann 窗；補零及峰值插值不創造新的來源時間資訊。

## 檢驗與後續規範

新增測試驗證48 kHz PCM與1024點塊、120 ms接收批次相互獨立；排除混合來源／上一輪／暫停；偶數中位數與間隔抖動；原始硬體interval(ms)與觀測值分開；22模組單位註記；lx與數位像素；Excel同時保存degree/rad及取樣／接收條件。

44項計算與匯出測試通過。瀏覽器流程另外驗證22項入口說明、觀測50 Hz→20 ms、SI有效質量可編輯、暫停／繼續／結束不自動下載、手動真實XLSX、真實PeerJS配對及模組同步、亮暗中英和窄螢幕。瀏覽器測試沒有代表實體iPhone的校準結果；課堂前仍需在實際裝置確認感測可用與實測間隔。

後續新增模組必須：列出量及單位、轉換規則、原始尺度、時間來源、取樣／傳送／畫面排程、資料缺口策略及模型限制；同步更新入口、實驗頁及Excel。未校準相機／麥克風不得冠上lx、Pa或dB SPL。凡改變時間窗或傳送常數，應引用同一套 timing constants 並更新對應測試。若追求跨手機同步或硬體誤差規格，需另外設計時鐘同步／校準與驗證流程。
