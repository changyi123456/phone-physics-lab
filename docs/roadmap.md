## P1：聲學

| 模組 | 輸入／圖表 | 前置條件與驗收 |
|---|---|---|
| 聲音頻譜 | PCM 波形、FFT 幅度–頻率、主頻 | 麥克風授權、實際 sampleRate、echoCancellation/noiseSuppression/autoGainControl 支持與實際值；已知音源對照 |
| 頻率歷史 | f(t)、頻率–時間熱圖 | 固定分析窗口、窗口時間戳；不能把每個窗口完整捕捉當成當然 |
| 聲控秒錶 | 音事件時間、事件間隔、序號–Δt | 來源端精確時間；若需手機端處理觸發，先確認是否允許超出純感測封裝；不能由跨網路到達時間觸發 |
| 碰撞分析 | 反彈事件間隔、推導高度、相對能量 | 噪音觸發與漏事件驗證；高度／能量為模型推導，不宣稱直接測得 J |

純前端可在手機擷取 PCM 後傳電腦分析，但資料量與網路抖動需新傳輸預算。原 phyphox 的 phone-side audio analysis 不能直接套用手機純 sensor 的架構。若調整架構，寫入新決策再實作。

## P2：既有運動來源延伸

- 加速度頻譜、振動頻率歷史、運動觸發秒錶。
- 多輪參數掃描，例如 T²–L、T²–m；需先設計本次工作階段多輪匯出，保持無帳號。
- 彈簧常數 k 推導、向心圖線性擬合與半徑估計，明列幾何與質量模型。
- 量測誤差、重複試驗統計、殘差圖與進階模型。
- 教師自訂實驗配置，沿用 extension-guide 的 manifest 與版本契約。

## P3：新來源、能力條件與器材

| 項目 | 規劃狀態 |
|---|---|
| GPS／戶外運動 | 查 geolocation 精度、更新率、前景限制；速度與位移的品質驗收後開發 |
| 相機亮度／顏色／光學秒錶 | 查曝光、自動調整、ROI、frame timing；像素亮度不等於 lux |
| 光譜分析 | 需要光柵與波長校準；相機支持與處理頻寬先驗證 |
| 磁場、氣壓、照度、接近、LiDAR／ToF | 逐項查原生與瀏覽器落差；不能以 DeviceOrientation 的姿態／航向替代三軸磁場 µT。若純網頁不能讀取，列受限而非要求安裝 App |
| 外接感測器 | 查各瀏覽器的 Bluetooth/USB 能力；需設備與新授權流程，另確認範圍 |
| 兩手機同步／全班比較 | 與目前各組獨立產品不同；同步精度與介面重新決策，不偷偷加入 |
