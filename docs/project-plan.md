版本：1.0｜日期：2026-10-08｜狀態：使用者已確認並授權初版實作。

追加確認：電腦與手機都提供亮／暗主題及繁中／英文介面，指引、圖表、按鈕、Excel 欄名一起翻譯。localStorage 只記外觀／語言偏好，不保存量測歷史。

## 1. 目標與邊界

高中教師與學生開網站，以一台電腦配對自己的手機進行物理實驗。手機免 App，負責瀏覽器感測與傳輸；電腦負責指引、操作、校準參數、分析、圖表與單次 Excel 匯出。30 組可獨立使用，不做班級資料聯動。

兩端需上網，可使用不同 Wi-Fi／行動網路。應用全前端、靜態 HTTPS 部署，免登入、無雲端紀錄、無歷史資料庫。每次量測結束保留結果，使用者手動匯出一個真正的 `.xlsx`；資料暫存在電腦記憶體，離開頁面會遺失，尚未匯出時提示。

「全前端」不代表網路配對無服務依賴。沿用 Harbor Run 的 PeerJS/WebRTC、QR 邀請連結與隨機房間識別；依賴外部信令、STUN，以及必要時的 TURN 中繼。既有 PeerJS 1.5.5 套件的預設配置包含公共 TURN；官方文件部分預設範例不同，應核對實際套件並記錄版本。公共服務的可用性與校園網路放行不能保證，失敗必須顯示重試與網路建議。初版不新增付費服務，連線適配層可替換。

## 2. 首版實驗與圖表

## 3. 核心流程

電腦選實驗 → 顯示原理／公式、器材擺放與校準指引 → 建立 QR 配對 → 手機按「啟用動作感測」授權 → 實際收到資料後判斷能力 → 校準 → 電腦開始量測 → 即時數據／分析結果 → 結束 → 檢查結果 → 手動下載 Excel → 新一輪。

手機主要呈現配對、權限、取樣、量測狀態與明顯的相對歸零按鈕，不建立手機實驗分析主介面。授權需由使用者按鈕觸發。校準由電腦側利用穩定預覽窗口計算；不把含重力加速度直接全部扣成 0。保留未套用校準的接收資料、角速度偏移及姿態基準。量測途中校準鎖定，避免同一輪模型跳變。

## 4. 資料與時間契約

每個事件保存 runId、seq、source、t（手機端瀏覽器事件時間、相對本輪起點）、數據欄位、螢幕方向與來源時間資訊。motion 與 orientation 分開記錄，不把最近一次姿態角當成同時取樣。軸向固定於裝置座標，不隨畫面橫直向任意改變。缺失欄位為 null，不能填 0。

瀏覽器事件資料為系統處理後資訊，不宣稱硬體原始取樣或固定 50 Hz。顯示實際事件間隔估算的取樣率。手機事件時間用於物理分析，RTT／到達延遲屬連線品質，不拿電腦接收時間計算週期。

可靠有序 DataChannel＋應用序號與 ACK。手機有限暫存，短斷線後補傳；重複資料按序號去重，跨 runId 不接受。暫存到上限或離開頁面造成的永久缺漏保存品質事件。停止量測有最終序號確認；未收到完整停止資料時顯示狀態，允許明確標示不完整的匯出。

分析與圖表相互獨立：圖表可取最近窗口並降採樣，Excel 保存本次接收的完整資料。振動分析先取連續有效區段，按實測中位間隔重採樣，再估算週期與頻譜；不跨背景／感測中斷區段做自相關。資料不足或過於不規則時，數值顯示未能估算，不能輸出假精確答案。

## 5. 失敗與安全邊界

- 無 HTTPS／授權遭拒／感測無資料：分開顯示原因與操作方式。
- 能力以實際有效事件確認；缺少必要欄位時不能開始對應實驗。
- 手機需維持頁面前景，不鎖屏。嘗試 Wake Lock，但不以其成功作為背景可持續感測的保證。
- 隱藏／回前景、網路斷線、補傳、序號缺漏、停止逾時：保留品質事件與時間，圖上不連接跨缺漏線段。
- 房間隨機不可預測、只接受一支手機、配對 token 與協定版本驗證、數據範圍及批次長度驗證。只接受自身連線來源控制；示範模式與實機模式不可混入同一輪。
- 尚未匯出離開頁面／新一輪先確認。下載失敗保留本輪資料並允許重試。
- 無帳號資料。第三方服務可能看見連線中繼所需網路資訊；不對其日誌政策作無依據保證。TURN 中繼為 WebRTC 加密封包。

## 6. Excel 契約

一輪一個 .xlsx；數值為數值型儲存，單位寫入欄名與說明，缺失留空。至少包含：實驗資訊（版本、來源模式、時間、參數、能力）、Motion 資料、Orientation 資料（有則提供）、分析結果、自相關／頻譜（相關模組）、校準紀錄、品質事件。示範檔案名稱及內容清楚標記「示範」，不可冒充實測。輸出的分析與畫面使用同一核心計算結果。

## 7. 首版架構與介面

React + TypeScript + Vite；PeerJS + QRCode；Chart.js；SheetJS CE。依賴鎖定版本、來源授權記錄，應用 bundle 不含管理用秘密。

模組分離：core/types、registry、analysis、recording、export；platform/sensors、link；components/Desktop、Phone、Plot、Instructions。計算可由 Web Worker 執行，控制 render 頻率以避免每筆事件重畫全部圖表。

設計：白色工作區、深藍實驗側欄、藍色主要動作、三軸一致配色。電腦版左實驗選單、中數據圖、右手機連線；手機版單欄、大授權與校準按鈕。操作指引在量測前可見。提供標示清楚的示範模式供免手機預覽，預設無合成實測數據。

## 8. 驗收與交付

首版瀏覽器暫定：電腦 Chrome/Edge/Safari；手機 iPhone Safari／Android Chrome。實際版本、設備與網路條件寫入驗收記錄。

1. 完整配對→加速度→圖表→Excel：兩瀏覽器端自動化與真機分開驗證。
2. 軸向／單位／校準：已知向量與角速度測試，穩定才可校準；不破壞含重力原值。
3. 振動：已知 0.5–4 Hz 訊號及不規則間隔 fixture 驗證；不跨缺漏分析；真實擺、彈簧對照人工多週期計時並記錄偏差。
4. 向心關係：以 a=rω² 的已知 fixture 驗證圖與匯出；真機使用固定半徑旋轉裝置。
5. 30 組×10 分鐘：先測核心資料隔離與接收完整性，再測瀏覽器配對及實際課堂。核心模擬通過不代表 30 組真機驗收完成。
6. 單次 Excel：回讀檔案核對分頁、列數、時間、數值、單位、缺漏、模式與參數。
7. 斷線／背景／重連／停止逾時／離頁：驗證資料保留、提示與不完整匯出。

交付順序：完整加速度流程 → 基礎三模組 → 振動兩模組 → 向心模組 → 多組、跨網路與真機驗收。首次交付為可操作初版，未執行的硬體／課堂驗收明確標為待驗。
