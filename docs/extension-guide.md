# 擴充規範 v2

適用本專案所有新實驗。先閱讀 project-plan.md；手機網頁、全前端、獨立配對與單輪 Excel 為不可暗中變更的產品契約。

## 模組登錄

在 `src/core/registry.ts` 加入唯一 id、繁中名稱、簡述、requiredCapabilities、參數（key／預設／範圍／單位）、指引步驟、公式、適用條件、圖表 specs。分析由核心純函式處理；UI 不嵌入物理公式。

每個圖表定義 id、x/y 名稱與單位、series 欄位、線／散點、窗口與更新策略。同物理量配色一致，xyz 分別藍／青綠／橙。結果清楚區分量測值、輸入值、推導值。新圖不得只因圖表元件支援而加入無教學意義的數據。

## 新感測來源

1. 查官方瀏覽器文件與實際事件；硬體存在不代表網頁可用。
2. 不變更既有 sample 欄位的意義；新增 source 及 schema 版本。
3. 固定軸向、時間單位與物理單位，明列 browser API 原單位與轉換。不同来源不同時間序列；對齊須有算法與最大有效誤差。
4. 欄位未知為 null；能力經有效事件確認。permissions/無事件/值失效分開處理。
5. 新來源沿用 runId、seq、ACK、有限暫存與停止確認；大型資料（PCM、影像）另定記憶體、頻寬、窗口與匯出政策。
6. 在 iPhone Safari、Android Chrome 各驗證；無支持的平台顯示原因，不提供合成資料冒充測量。

## 分析品質

每個算法列輸入、輸出單位、窗口、濾波、重採樣、模型假設與 failure reason。保留接收資料；衍生序列不能覆蓋原序列。網路到達時間不能取代來源時間；插值僅用於已說明的分析，不寫成原量測。

測試必須能偵測物理錯誤：已知頻率、已知軸向與單位、噪音／抖動／缺漏／短資料／常數信號。不能只重述實作本身。低取樣率、混疊、嚴重缺漏或不成立條件需回報狀態而非假精確數值。

## 校準

定義 baseline 物理意義、穩定門檻、保留欄位、失效條件。相對 0° 不等於真水平；角速度靜止偏移不能拿來校正加速度重力。一輪內固定校準版本；變更需建立新輪，或另設有時間與版本的段落契約。校準 UI 必須有明顯可點按按鈕與完成證據。

## Excel

每個模組新增 export sheet spec；數值存 numeric，單位與模型條件明列。時間序列、頻率序列、自相關序列使用各自座標；不錯配列。包含模式（實機／示範）、實驗參數、校準及品質事件。schema/分析版本寫入資訊表。用回讀測試核對欄名、列數、數值及缺失。

## 上線與完成條件

- 指引、公式、圖表與能力限制完整。
- 已知訊號分析通過；不支援及缺漏分支有測試。
- 桌機與手機 UI 可讀、操作不溢出；停止與匯出可重試。
- 真機驗收明列設備／系統／瀏覽器／網路／取樣率與偏差，沒有硬體證據則標為待驗。
- 新依賴鎖定版本、查來源與授權；新增外部服務不得暗中增加帳號、後端或付費要求。
- 維護 roadmap 勾選進度、acceptance 實測結果、README 使用方式。

## v0.2 已採用的契約

來源及大型資料契約見 measurement-catalog.md。新增模組登錄於 advanced-registry.ts，分析於 advanced-analysis.ts，擷取於 SourceHub；UI 與Excel沿用分析結果。暫停與繼續是同runId的新segment，校準不變；所有算法必须明確不跨segment或品質缺口。教師設定schema1是宣告式有限参数，匯入檔≤10KB，不允許腳本。

## 暫緩器材範圍

本版不含外接器材、氣壓、接近、深度及光柵光譜。未來若重新授權加入，必須重新定義來源時間、物理單位與校準，不能假設手機瀏覽器已可讀取；依本次產品決策不預留可點按的無功能器材入口。
